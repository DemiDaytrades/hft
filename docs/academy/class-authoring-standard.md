# HFT instructional experience standard

Use **experience → visualize → predict/interact → explain → apply → check understanding**. Begin with a problem the learner can experience before introducing its name. Original visuals must demonstrate relationships rather than decorate prose. Use concise explanations, meaningful examples, misconception handling and deeper explanations where needed; do not remove academic substance to reduce reading.

Vary the presentation to suit the concept: scenario decisions, comparisons, progressive demonstrations, timelines, sorting, tap/select labels and short explanations. Explain why a response fits or needs another look. Give a respectful retry. Never imply exploratory UI practice awards instructor-approved mastery. Save durable assessed work through the existing Academy authority.

Preserve immutable academic versions, objective/competency mappings, distinct evidence, individual written review, targeted remediation, revision/history and legacy progress. Presentation revisions may reorganize the same instruction without changing the meaning or requirements of the assigned academic version. Changed academic requirements need a new immutable academic definition and explicit enrollment policy.

**Homework format must match the skill.** Do not copy Class 1’s A–F mechanically:

| Skill | Suitable homework |
| --- | --- |
| Pips | Calculations with working |
| Candlesticks | Identify, build and read candles |
| Market structure | Chart markup with reasoning |
| Risk management | Position/risk scenarios |
| Psychology | Decision scenarios and reflection |
| Trade planning | Build and justify a trade plan |

A permanent Study Guide summarizes concepts in fresh words, with useful diagrams, examples, misconceptions, vocabulary and self-checks. It is not a transcript of the interactive lesson.

Student navigation uses available/in-progress/completed/locked/coming-later language. Internal blueprint/authored/published/assessment-ready metadata belongs in protected instructor tools. Coming-later content is never falsely playable.

Use native keyboard/touch controls, labeled diagrams and text equivalents, visible focus, reduced motion and feedback expressed through words/icons as well as color. Sorting cannot require dragging. Verify actual authenticated desktop and approximately393px Chrome; CSS/render tests alone cannot certify mobile layout.

Class 1 is the local reference implementation, subject to experience acceptance. This document does not authorize Class 2+, deployment, production mutation, Chart Lab or stage-assessment implementation.
