No deployment, production reads/writes, production migrations, real-student edits, messages, Stripe activity or real plan/path generation occurred for this task. 1. **Duplicate-question audit.** Audited 446 capture fields plus 138 Intake V2 student/instructor keys and 134 downstream entries. Existing compatibility helpers were wrappers, not semantic mappings. Repetitive instructor summaries and manual placement fields were separate editable authorities. See `docs/audits/2026-11-07-capture-field-audit.md` and `2026-11-07-downstream-flow.md` (these describe the pre-change state).

The final matrix is reconciled with executable projection. Canonical category registry is `lib/consultation-review/canonical.ts`.
3. **Redundancy removed/derived.** New/resumed canonical capture uses a short human review instead of requiring the old twelve instructor fields, manually repeated factual summary, starting level or track. Compatible legacy facts are explicitly adopted into missing canonical fields with original source references. Subsequent duplicate legacy edits are rejected by both UI and server. Existing canonical answers win; conflicting evidence remains visible.
4. **Structured controls.** Historical demo/live use, broker experience and current platform access use existing Yes/No values, with no implicit default. Markets use existing options, preserving custom saved values. No invented overall-experience or MT5-proficiency scale was introduced. Existing specialized financial controls remain contract-based.
5. **Narratives preserved.** Goals, motivation, barriers, explanations, success definitions, observations and private notes remain text. Combined 6–12 month visions remain intact; they are not arbitrarily split into separate dated goals.
6. **Conditional behavior.** Live-account history is hidden when never live; broker names require reported broker experience; education notes/negative-experience reflections are hidden for explicit No. Never-traded loss/win reactions cease blocking only in the new canonical-review workflow. Hidden retained data is preserved. Existing financial question gates are retained.
7. **Instructor review.** The default workspace presents facts, analysis, missing information and conflicts, then asks match/partial/contradiction/not-observed, assessment/practical/chart requirements, optional observations/private notes and an explicit review attestation. Approval/override stays in the existing Financial Plan and Learning Path workspaces. No duplicate placement authority is created.
8. **After-call summary.** A short read-only SYSTEM_DERIVED recap includes name, reported markets/demo/live/platforms, goals, schedule and support preferences plus relevant original legacy context. Complete facts and source references remain available in a disclosure. Correct the canonical source or use an explicit instructor override; there is no independent summary copy to drift.
9. **Provenance.** STUDENT_REPORTED, INSTRUCTOR_OBSERVED, ASSESSMENT_DEMONSTRATED, SYSTEM_DERIVED and INSTRUCTOR_OVERRIDE remain distinct across fact, observation and assessment evidence. Staff entry of a student's answer does not relabel it as observation. Corrections retain before/new values, before/new provenance, authenticated actor, timestamp and reason; overrides require a reason. Mutation and history inserts are atomic with revision guards. A failed history insert rolls back the change.
10. **Legacy records.** Opening analysis does not create or alter records. Legacy-completed is visibly distinct from V2-complete. Explicit compatible adoption is source/digest checked and fills only missing values. Unknowns never become No, None, zero, consent, financial ranges or mastery. New revisions copy known student answers from the prior completed V2, preserving the completed snapshot, while collecting new acknowledgment/review evidence. Unmapped original answers remain visible; distinct legacy-only facts retain their owner and revision history.
11. **Completion validation.** Exact server-required missing items have navigation to their source section; a missing-only filter reduces editing. READY TO FINALIZE requires no pending compatible adoption and passing validation. Genuine acknowledgments and a review for the exact saved revision are required. Later source edits invalidate that review. Empty knowledge/behavior matrix values are missing rather than accepted by key count. Optional answers do not become new requirements.

## Repeatable browser procedure

1. In the application containing this candidate, sign in as authorized instructor; open `/admin/student-intake-v2`, select the test student.
2. Review Facts, analysis & instructor review. Start/enable the canonical workflow if requested; inspect compatible sources, then Use compatible saved answers.
3. Review generated summary, financial findings, educational evidence and conflicts. Use exact missing-item links and Show missing required questions only to finish capture. Save each section.
4. For factual corrections, use the canonical field, choose the correct reported/override evidence source and enter a reason for overrides. Inspect private history to verify before/new values.
5. Capture only genuinely confirmed acknowledgments. Complete concise human review and explicit attestation after the final fact/acknowledgment save.
6. Confirm READY TO FINALIZE; open Review & Complete, check saved validation, attest and finalize. Refresh: completed snapshot is read-only.
7. Use the explicit Financial Readiness and Learning Path links for later generation/review/publication/assignment, subject to separate authorization for real students. No publication occurs by viewing the intake.
